# 05: Adapter opencode

**What to build:** Prawdziwy agent opencode podpięty pod kręgosłup, E2E. Plugin w katalogu pluginów opencode (pakiet stow `agents/`) woła wspólny `agent-hook`: `permission.updated` → notify, `session.idle` → done, `session.status` busy → working, `session.deleted` → clear. Payloady eventów zweryfikowane z typów SDK zainstalowanej wersji (`properties.sessionID`). Instancje przez `ai opencode`. Ryzyko jak w 04: PPID-łańcuch z procesu opencode do foot — zweryfikować E2E, udokumentować obejście jeśli nie działa.

**Blocked by:** 01 (kręgosłup — agent-hook, ai, focus-window).

## Comments

- **Korekta założenia specu (kluczowa):** zainstalowany binarny opencode to **v2.0.15** — nowa architektura, w której **nie istnieją** `permission.updated` / `session.idle` / `session.status` (to słownik SDK v1 — `@opencode-ai/plugin` 1.17.13 w `~/.config/opencode/node_modules` jest v1 i nie odpowiada binarce; założenie z issue brało stamtąd `properties.sessionID`). Rzeczywisty słownik v2 zweryfikowany live (probe-plugin dumpujący eventy) + w stringach binarki: event = `{type, created, location?, data: {sessionID, ...}}`. Mapowanie wg intencji specu: `session.inbox.enqueued` z `item.type == "user"` → working (analog UserPromptSubmit→working z adaptera claude), `permission.asked` → notify, `permission.replied` → working (user zareagował, agent wznawia), `session.execution.started` → working, `succeeded`/`failed` → done (failed z message), `session.deleted` → clear. `session.execution.interrupted` niemapowane (user sam przerwał, jest przy oknie; steer i tak pali kolejne `started`).
- **Forma pluginu:** zwykły default export `{id, setup(ctx)}` — zweryfikowane live, **bez** importu `@opencode/plugin` (pakiet v2 nie jest zainstalowany lokalnie, a loader akceptuje plain obiekt). Subskrypcja `ctx.event.subscribe({signal})` + cleanup przez AbortController; wołanie `agent-hook` przez `spawnSync` (ta sama lekcja co w 04: serializuje kolejność zdarzeń sesji, done nie wyściguje clear).
- **PPID-walk — obejście:** interaktywny TUI bez flagi startuje shared background service, który (a) **przeżywa zamknięcie okna** (detached daemon), (b) **drugie okno podłącza się do serwera pierwszego** — plugin instancji drugiego projektu rozwiązywałby się na PID foot **pierwszego** okna (zweryfikowane E2E: dwa okna → oba SETUP w serwerze 51599 należącym do okna nr 1). Obejście: `ai` woła opencode zawsze z `--standalone` (TUI bez argumentów → `opencode --standalone`; `run`/`mini` → flaga **po** subkomendzie — `opencode --standalone run` sypie „Unrecognized flag”, stąd dwa przypadki we wrappery). Standalone = prywatny serwer (`serve --stdio --port 0`) jako dziecko TUI → dziecko foot → łańcuch nienaruszony; pid w state == pid okna w `hyprctl clients`, focus działa.
- **Replay backlogu (guard):** shared service przy subskrypcji pluginu **odtwarza durable backlog** (stare eventy → ghost state-file'y pid 0, nieprunowalne z definicji spine). Guard jednowierszowy w pluginie: `event.created < Date.now()` na starcie setup → skip. Ścieżka standalone nie replayuje (zweryfikowane: 0 starych plików). Sufit udokumentowany: przez persistent service stare interrupted sesje dostają świeże `working` przy resume → wpisy pid 0; twarda konwencja `ai opencode` (standalone) omija service w całości.
- **Widget waybar live:** `agents-widget` na prawdziwym state dir — 0 przy samych working, 1 z tooltipem `opencode · proj — gotowe` po dorzuceniu done, z powrotem 0; sygnał `pkill -RTMIN+8 -x waybar` trafia w żywy waybar (pid 1264).
- **Notification path live (po doinstalowaniu dunsta w trakcie sesji):** na początku dunst nie był zainstalowany (E2E zakończone bez popupów — patrz commit 1724ea1), po doinstalowaniu re-zweryfikowane pełne E2E: critical `notify` dostarczony i wisi (helper dunstify blokuje, displayed=1), `dunstctl action` → fokus trafia w pid ze state (`ai · bash` 131916 mimo że activewindow był wcześniej na Brave); `done` → normal (timeout 5s w dunstrc — klik trzeba oddać szybko, skrypt E2E kliknął w <1s). Degradacja graceful bez dunsta (brak binarki → brak popupu, brak crasha) — zachowana.
- Testy: adapter celowo bez testów automatycznych (spec: cienkie wrappery, pokryte seamem E2E); istniejący suit `bash agents/tests/test-agents.sh` → ALL PASS (bez zmian; zmieniony tylko `ai` — przez niego test nie przechodzi bo testy nie wołają `ai`).
